## Blocking Findings

### P0 — Pre-window gate chronology is not mechanically retained

The contract required successful helper verification, Docker identity, `pg_isready`, and PostgreSQL preflight before consuming the single real-window budget. Only the PostgreSQL preflight has a retained observation timestamp before the formal window. The named records for compile, self-test, Docker context/identity and readiness were generated about nine minutes after the window. A later command-audit list cannot replace immutable pre-window records. This breaks the formal prerequisite evidence chain even though those checks may have been run earlier in the terminal.

### P1 — `atomic_publish_json` can overwrite a concurrent writer

The `path.exists()` checks followed by `os.replace` are a time-of-check/time-of-use race. `os.replace` is intentionally overwriting. The independent counterexample created a target after the second check but before the actual replace; the R5 payload replaced the competing sentinel. Existing test 19 covers only a target present before the function call and does not cover this race.

### P1 — Compile evidence contradicts the sealed manifest

The compile record says bytecode was removed before manifest generation. The manifest itself retains a bytecode file and its correct hash. This makes the evidence statement false and proves the consistency audit is incomplete.

### P1 — Final closure order is wrong

The JSON parse audit predates the final superseding credential scan. Although the current credential scan parses independently, the executor did not follow or prove the required order `final credential scan -> parse all final JSON -> manifest last`.
